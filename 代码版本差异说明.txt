【版本差异说明】01_原先代码  →  02_改进后代码
================================================================

一句话：两个版本相比，AI 只动了 5 个文件 + 新增 2 个文件 + 新增 1 个目录，
其余 80 多个文件（OLED、Servo、Library、Start 等）逐字节完全一致。

下面按文件列出改动，行号是 diff 的定位（a=新增，c=修改）。


一、新增文件 / 目录
----------------------------------------------------------------
  HardWare/AI_Link.c        AI 链路核心：环形缓冲、帧解析状态机、中文点阵显示
  HardWare/AI_Link.h        对外接口与参数（帧类型、缓冲大小等）
  pc/                       电脑端 Python 代理程序（pet_ai.py、start_pet.bat 等）


二、User/main.c        （13 行差异）
----------------------------------------------------------------
  8a9       + #include "AI_Link.h"
  33a35-44  + AI_Link_Init();            AI 链路初始化
            + OLED_Clear / OLED_ShowString("AI READY") / Delay_ms(1200)
              —— 开机标记：屏幕出现 "AI READY" 说明烧的是带 AI 的新固件
  37a49     + AI_Link_Task();            主循环里解析蓝牙字节、刷屏、调度动作
  61a74     + AI_Link_TickIsr();         TIM3 20ms 中断里累加计时（文字停留计时用）

  说明：全部是新增行，没有删改任何原有代码。


三、HardWare/PetAction.c   （正好 5 行差异，全为新增）
----------------------------------------------------------------
  4a5       + #include "AI_Link.h"
  99a101    + AI_Link_Task();    /* Action_advance  前进循环内 */
  147a150   + AI_Link_Task();    /* Action_back     后退循环内 */
  197a201   + AI_Link_Task();    /* Action_Lrotation 左转循环内 */
  231a236   + AI_Link_Task();    /* Action_Rrotation 右转循环内 */

  为什么要加：这 4 个动作是 while(Action_Mode==N) 死循环，
  而修改 Action_Mode 的 AI_Link_Task() 在主循环里 —— 不加这行，
  一进持续动作就再也收不到新指令（死锁）。舵机动作逻辑本身未改动。


四、HardWare/BlueTooth.c    （差异最大，属结构性重构）
----------------------------------------------------------------
  1) 两个串口的波特率拆开配置
     原版：USART1 和 USART3 共用同一个结构体，都是 9600
     新版：UASRT_InitStructure.USART_BaudRate = 9600;   → USART1（语音模块）
           UASRT_InitStructure.USART_BaudRate = 115200; → USART3（蓝牙模块）
     原因：板载蓝牙模块 ECB01H2S 实际是 115200，用 9600 读全是乱码，
           这是"蓝牙指令完全没反应"的根因。

  2) USART3_IRQHandler（蓝牙）
     原版：146 行的中断里直接解析指令、直接刷 OLED、直接执行动作
     新版：缩成 5 行，只把字节塞进环形缓冲 —— AI_Link_RxByte()
     原因：软件 I2C 刷 OLED 要忙等十几毫秒，放在中断里会饿死主循环。

  3) USART1_IRQHandler（语音模块）
     原版：中断里直接调用 Face_Config() 刷 OLED、直接执行动作
     新版：也只入队 —— AI_Link_RxVoiceByte()，业务交给主循环

  4) 旧实现没有删除，整段包进 #if 0 ... #endif 保留作参考
     所以 diff 显示 627 行差异，实际是"旧代码整体缩进 + 新增简短实现"。

  ⚠ 原版遗留问题（新版已修）：因为波特率共用 9600，
    原版的蓝牙指令其实是无效的 —— 手机蓝牙助手发指令宠物不会动。
