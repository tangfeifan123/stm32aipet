# 桌面宠物接入 DeepSeek AI（完整说明）

本文档对应**当前已实现的功能**：AI 对话 + 中文上屏 + 颜文字；语音目前用**电脑音箱**朗读（宠物本体发声属于后续扩展，本版未实现）。

---

## 一、整体架构

主控是 STM32F103C8T6（64KB Flash / 20KB RAM），**不能自己调 API**：DeepSeek 强制 HTTPS/TLS，握手就要 16~32KB RAM，还需要 TCP/IP 协议栈和 WiFi 物理层，这芯片一样都没有。

所以走**蓝牙代理**：电脑调 API，把结果翻译成「表情 + 动作 + 一句话」，通过板载 `ECB01H2S` 蓝牙透传模块发给单片机。

```
你说话 → pet_ai.py(电脑) → DeepSeek API → JSON(表情/动作/回话)
              │
              ├─ 中文渲染成 128×64 点阵(IMG 帧) → OLED 显示
              ├─ 表情/动作编号 → 舵机 + 表情
              └─ 语音：电脑音箱朗读（Windows SAPI）
                （数据经 BLE → ECB01H2S → USART3 → STM32 解析）
```

## 三、关键结论（踩过的坑）

1. **蓝牙串口是 115200，不是 9600**。原代码里 USART1（语音）和 USART3（蓝牙）共用一个 9600 结构体，导致收到的全是乱码、命令全部无效。已拆开：`USART1=9600`、`USART3=115200`。
2. **中断里刷 OLED 会饿死主循环**。原代码在 USART1 中断里直接调 `Face_Config()`（软件 I2C 忙等十几毫秒），只要语音模块吐字节就永久重入、主循环一次都跑不到。已改成「中断只塞环形缓冲，业务全在主循环 `AI_Link_Task()` 里做」。
3. **舵机动作会拉低电源、蓝牙掉线**。表现是"不动舵机一直稳定，一动作就断"。软件已加 `safe_send()` 自动重连兜底，根治靠电容/独立供电（见第八节）。

## 五、烧录与运行

### 1. 烧录

Keil 打开 `Project.uvprojx`，F7（编译）→ F8（烧录）。编译 0 错误 0 警告，Flash 约 13KB/64KB，RAM 约 4.2KB/20KB。

### 2. 装依赖

```bash
cd pc
pip install -r requirements.txt   # bleak + requests + pillow
```

### 3. 设 API Key（到 platform.deepseek.com 申请）

```cmd
setx DEEPSEEK_API_KEY "sk-你的key"
:: 设完要重开一个 cmd 窗口才生效
```

### 4. 跑起来

```bash
python pet_ai.py --addr EC:B2:AA:60:49:00 --voice
```

- 不指定 `--addr` 会自动扫描匹配
- `--demo` 离线演示（不调 API），`--ping` 只测链路
- `a<数字>` 直接做动作，`c` 清空上下文，`q` 退出

## 六、屏幕与语音

### 6.1 中文上屏（已实现）

Flash 塞不下完整中文字库，所以用「**电脑渲染、单片机显示**」：

1. 电脑用 Pillow + 微软雅黑（`C:\Windows\Fonts\msyh.ttc`）把中文渲染成 128×64 单色点阵；
2. 分 8 页（每页 128 字节）通过 `IMG` 帧发过去；
3. 单片机用 `OLED_ShowImage` 上屏，8 秒后切回表情。

- 16px 字号，一行 8 字、最多 4 行（32 字），超过截断；
- 渲染/发送失败自动退回英文上屏（TALK 帧）。

### 6.2 颜文字

`SYSTEM_PROMPT` 让 DeepSeek 偶尔在句尾加 `(≧▽≦)` `(・ω・)` `OvO` 等颜文字；语音播报前用 `strip_kaomoji()` 去掉符号，避免音箱念怪音。

### 6.3 语音（当前：电脑音箱）

- **当前实现**：`--voice` 用 Windows SAPI 朗读中文，零额外依赖，中文由 `Microsoft Huihui` 念；
- **说明**：板载 SU-03T1 只能播放平台预置、随固件烧入的词条，念不了 AI 实时生成的句子，所以本版没有让宠物本体发声；
- **后续方向**：可加装串口 TTS 模块（如 SYN6288），由单片机从 USART1 发 GBK 文本实现本体发声，**本版未实施**。

## 七、通信协议（二次开发）

```
0xAA 0x55 | TYPE | LEN | DATA[LEN] | XOR(TYPE, LEN, DATA...)
```

| TYPE | 含义 | DATA 结构 |
| --- | --- | --- |
| `0x01` | AI 回复 | `[face, action, speed, "英文文本"...]` |
| `0x02` | 心跳 | 空，STM32 回 `0x06` |
| `0x03` | 纯文字 | `"英文文本"...` |
| `0x04` | 图片帧 | `[face, action, page, 128字节点阵]`，8 页拼整屏 |
| `0x05` | 语音帧 | `GBK 编码中文文本`（驱动已预留，本版未接硬件） |

- `face` 0~6、`action` 0~15，对应 `Face_Config.c` / `PetAction.h`
- `LEN` 上限 131（图片帧要 131），文本帧仍是 60 字符
- 校验：从 `TYPE` 到最后一个数据字节逐字节异或
- 加 `0xAA 0x55` 帧头是为了和老单字节指令（`'0'`=0x30 正好是"蹲下"）隔离

## 八、排错

- **扫不到 / 连不上**：模块被手机占着；电脑蓝牙版本低于 4.0；模块没上电。
- **连上没反应**：先确认蓝牙模块串口是 115200（本仓库已配好）；检查 PB10/PB11 是否交叉接。
- **舵机一动就掉线**：供电问题。舵机电源并 470~1000µF 电解电容 + 0.1µF 瓷片；或舵机独立供电（共地）；蓝牙模块 VCC 再并 100µF；别用 500mA 的 USB 口裸跑四舵机。
- **屏幕没中文**：`render_cn` 渲染失败会退回英文，看终端 `屏幕显示:` 那行；确认 Pillow 装了、`msyh.ttc` 存在。
